# Benchmarks

Every result, good or bad, gets a row here (ground rule 1), measured with the
section 7 protocol. The raw bench JSON for each row is in `bench/results/`.
Every result is compared with stock llama.cpp on the same machine and model
file, run the same day.

## Results

**Kera's writing speeds from `tools/compare` on 15 and 16 Oct are too high** (the rows marked so below) and **can't be
measured again**: the Minisforum was sold on 10 Nov 2026 (D-038) before a new run could be made. They stay here as
what was measured, with the flaw named; they are no longer quoted on the public page. Each prompt was asked three times in a row on one server, and from the second time Kera's guesser
(copying from the chat: llama.cpp's ngram-mod, one table for every request a server gets) could copy its own earlier
answer; with two of the three runs able to copy, the median could be a copied one. Checked on the cloud CPU with
Qwen3-0.6B, the code prompt asked three times in a row on one server: 37 tok/s the first time, then 89 and 78, with
200 of 208 guessed words kept each time. Stock llama.cpp's and Ollama's speeds, Kera's with guessing off, and every
wait for the first word are not affected. The long-document tests asked each document once, but in turn on one server, and the
documents start with the same files, so Kera's writing speeds there may be a little high too.
`tools/compare/compare.py` now starts every server afresh for each run (and for each document) and asks each prompt
once per server. Every `tools/compare` row: greedy (temperature 0, top_k 1), thinking off, answers of up to 256
tokens; Nemotron 3 Nano's own default (thinking on) wasn't measured.
