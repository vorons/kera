## Kera 0.1.0 preview 2: everything built so far, ready to try on the Minisforum

**What this is.** The second preview download. Since preview 1, Kera picks the right way to guess ahead for each
model and checks that it pays, keeps guessing on models streamed from the SSD, trains small adapters on your own
examples, has three opt-in speed modes that trade a little quality (each with its measured cost), and has an
optional ROCm add-on for the Minisforum's graphics chip. None of it has been measured on your hardware yet: every
gate waits for the agent to reach the Minisforum. Everything not labelled lossy gives exactly the model's own
answers.

**How to try it on the Minisforum**

1. Download `kera-v0.1.0-preview.2-windows-x64.zip` below and unzip it anywhere (it replaces preview 1).
2. Double-click `kera.exe` (if Windows warns, "More info", then "Run anyway"). The page shows your computer's
   speeds, your models and how fast each should run; **Run** keeps a model loaded for chat apps.
3. In a terminal in that folder:
   - `kera serve -m <model.gguf>`: the server for chat apps (OpenAI and Anthropic interfaces). By itself it now
     guesses ahead by copying from the chat, plus the model's own MTP head when the file has one, and every few
     hundred words it measures whether guessing pays, stopping when it doesn't. MoE models too big for memory
     stream from the SSD.
   - `kera finetune --model <Hugging Face folder> --data <examples.jsonl> --out <folder>`: a LoRA adapter from your
     own examples (one JSON line each: a chat, or a prompt and its answer). Load it with `kera serve -m
     <model.gguf> --lora <folder>\adapter.gguf`. It needs Python with the packages in `finetune\requirements.txt`.
   - Lossy modes, off unless you ask for them (costs in `docs/QUALITY.md`): `--lossy-kv8` (the chat's memory in 8
     bits, for longer chats in the same memory), `--lossy-route 0.05` (streamed MoE models: use an expert already in
     memory when the router scores it almost the same), `--lossy-reuse 0.15` (a document pasted again in the same
     chat is copied, not read again).
4. **The ROCm add-on (optional):** unzip `kera-v0.1.0-preview.2-windows-x64-hip-addon.zip` into the same folder (a
   `hip` folder appears next to `kera.exe`), then add `--backend hip` to a command. Check it first: ask the same
   question at temperature 0 with `--backend vulkan` and with `--backend hip`; the answers should match. Vulkan stays
   the default until the agent's exactness check passes on the Minisforum.

**What was built** (milestone by milestone in `docs/STATUS.md`)

- **M4:** the guesser switch: per chat, it measures each way of guessing (copying from the chat, the model's MTP
  head, a draft model) and keeps whichever writes fastest, "don't guess" included, and remembers per model which
  ones don't pay.
- **M6:** guessing on models streamed from the SSD starts low, because every checked word brings its own experts
  from the SSD; Kera logs how many extra experts each guessed word adds and predicts what a check would read.
- **M8:** the optional ROCm add-on (built the way llama.cpp's own release builds it), and plain-words advice when
  Windows gives the graphics chip too little memory.
- **M11:** `kera finetune` (MLX-LM on a Mac, Hugging Face PEFT elsewhere), and ESFT for MoE models (only the experts
  your examples use most are trained).
- **M12:** the three lossy modes above, and the quality tests behind `docs/QUALITY.md`.
- **M1:** the Shadow Bits risk test came out no-go, so M7 is skipped (`docs/M1_RISK_TESTS.md`).
- **A fix found while measuring:** llama.cpp keeps recent chats in memory, up to 8 GB by default, which squeezed a
  streamed model out of memory on a 15 GB machine and cut writing from 3 to 0.6 tokens a second. `kera serve` now
  sizes that cache to what the model leaves (1 GB while streaming); Kera's saved chats on the SSD keep the rest.

**Numbers so far** (the cloud test machine: 4 cores, 15 GB of memory, no graphics chip; not your hardware)

- 8-bit chat memory, Qwen3-1.7B: perplexity (how well it predicts a fixed text; lower is better) 18.964 without,
  18.973 with (+0.05%); JSON answers 44 and 45 of 50; 110 and 113 of 200 questions right. Half the memory per word.
- Reusing a pasted document, Qwen3-1.7B: the second message read 86 words instead of 374; 29 of 30 answers right,
  against 30 of 30.
- Cache-aware routing, Nemotron 3 Nano streamed with a quarter of its experts in memory: half the reads from the
  SSD per word (781 MB to 408 MB over the whole test); perplexity +0.1%; 163 of 200 questions right against 168,
  47 of 50 JSON answers against 48.
- Shadow Bits: the best nested draft guessed the next word right 85% of the time, but its full model was 38 times
  further from the original than plain 8-bit weights; plain weights with a small draft model predict about 1.8
  times the speed.

**Did the gates pass?** Not yet. Every gate needs a measurement on the Minisforum, the Mac or an NVIDIA machine.
