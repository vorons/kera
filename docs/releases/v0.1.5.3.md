## Kera 0.1.5.3: the engine underneath is updated to llama.cpp b12500

**What this is.** A patch release: Kera's own behaviour and settings are unchanged, but the bundled llama.cpp
moves from b11619 (14 Oct 2026) to b12500 (18 Nov 2026). The Linux download is the one built here; the Windows,
Mac, Spark and ROCm downloads are not built in this fork yet.

**What changed**

- llama.cpp b12500 is in the download. Kera's eight hooks were carried over: saved chats on disk, the guess-length
  controller, streamed experts, the model card's per-request sampling, reply shapes, several chats sharing the
  chip, and the settings filled in after llama.cpp has read them.
- Saving and loading a chat now uses llama.cpp's own batched tensor copies. Kera's smaller copy of that idea is
  gone. The bytes written are the same.
- Two fixes Kera had ported from upstream are now in upstream itself, so the ports were removed: token
  probabilities with guessing, and the handling of post-sampling probabilities.
- The N-009 fix stays: on a MoE model with a graphics chip, a greedy reply that has to replay accepted words still
  accepts them as chosen instead of re-checking them in a different batch and getting stuck.
- The saved-chat hook was adapted to upstream's new checkpoint and state-data types. The test that saves a chat,
  restarts the server and loads it again passes, as do the four cases where a state must *not* be reused.

**What was checked.** CPU build with warnings as errors; unit tests 20/20; reference-code checks 17 passed,
1 skipped; the tiny-model exactness, streaming and saved-chat tests in Linux CI. b12500 caps a slot at the model's
training context, so the tiny-model saved-chat test now uses shorter messages. No measurement of speed or answer
exactness on a graphics chip was possible here; that needs the owner's DGX Spark.
