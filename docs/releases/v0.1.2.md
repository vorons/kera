## Kera 0.1.2: 3D models, sound effects, faster pictures and music, a prompt improver

**What this is.** Version 0.1.2, open source (Apache 2.0). It adds two kinds of things to make, makes pictures and
music about twice as fast on the processor without changing how good they are, and fixes 22 bugs.

**New**

- **3D models** (`kera 3d`): a textured 3D model (`.glb`) from a picture, or from a description (Kera draws the
  picture first with an image model). It uses Microsoft's TRELLIS.2 through trellis.cpp, on the graphics chip. The
  model files (about 5 GB) are yours to download; `kera 3d --help` names them and their licences.
- **Sound effects** (`kera sfx -p "door creak" --duration 4 -o door.wav`): MOSS-SoundEffect v2 through audio.cpp,
  48 kHz, up to 30 s.
- **Prompt improver** (`kera image|video ... --improve-prompt CHAT_MODEL.gguf`, only when asked): a chat model
  rewrites a short description in more detail, keeping everything it says, and Kera shows both. The same words give
  the same rewrite, and a repeat comes from memory in seconds. `kera music` now shows how its own model rewrote the
  description (`--no-rewrite` turns that off).

**Faster, with the same quality**

- Pictures and music are made about twice as fast on the processor: a SD-Turbo picture in 20.8 s instead of 38.5 s,
  a 10 s song in 35.7 s instead of 57.8 s (the "drawing" step, the VAE decode, halves in both). The picture and music
  engines now use the same fast way of multiplying numbers as the chat engine. Checked against the model's reference
  code: the pictures are as close to it as before (46.9 dB against 46.7 dB, `docs/QUALITY.md`).
- The picture server loads its model when it starts, so the first picture is as quick as the rest. The music server
  keeps its models loaded between songs on computers with 32 GB or more.

**Fixed**

- The same seed now gives the same song (the music engine picked part of its seed at random each time) and the same
  picture on every graphics chip (the picture engine could choose its methods differently from one start to the next).
- Starting Kera a second time opens the one already running, instead of loading a second copy of the model (the
  likeliest cause of a report that only one person could use it).
- With `--backend auto`, one long document no longer makes everyone else wait.
- An ordinary NVIDIA graphics card is no longer taken for a DGX Spark-style shared-memory chip.
- 18 more, listed in `docs/NEGATIVE_RESULTS.md` (N-016).

**Tested** on the CPU: unit tests, the tiny-model exactness test, pictures served and drawn (with the prompt
improver), music, speech and video, and the 3D and sound-effect commands. **Not yet:** a real 3D model and sound
effect on a graphics chip (the models are 4-5 GB and 3D needs a graphics chip), and the speed-ups' size on the
Minisforum, the Mac and the Spark: these come with the next hardware runs.
