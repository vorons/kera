## Kera 0.1.0 preview 4: the back-end chosen for every message, several people at once, and open source

**What this is.** The fourth preview download, and the first under an open-source licence: Kera's own code is now
Apache 2.0 (copyright Kera Labs), and this release is the one published on Hugging Face (D-026). No gate has passed
yet; the new pieces below are built and tested in the cloud, and their measurements on the Minisforum come next.
Everything not labelled lossy gives exactly the model's own answers.

**What changed since preview 3**

- **The back-end is chosen for every message** (`kera serve --backend auto`, D-022 and D-024). With the ROCm add-on
  installed, Kera measures Vulkan and ROCm once on each model, then sends each message to the one that finishes it
  sooner: chats to Vulkan (it writes faster), long documents and their follow-ups to ROCm (it reads them about twice
  as fast). With memory free for two copies both stay loaded; otherwise one at a time, swapped when that pays. Each
  answer says which back-end gave it. Off by default until it is measured on the Minisforum.
- **Several people at once** (`kera serve --multi-user`, D-023): a new message is read before the rest of someone's
  long document, others keep writing while a long prompt is read, a start several chats share is read once, and
  requests can carry a priority. Off by default until it is measured.
- **Kera vs Ollama for the Mac**: a small app that downloads a mixture-of-experts model through Ollama, runs Kera on
  the same file, and races the two live for 10 minutes on chat, code, reasoning and a long document (D-025).
- **Open source**: Apache License 2.0.

**Numbers so far** (the Minisforum, Nemotron 3 Nano 30B-A3B, 16 Oct, preview 3's engine): Kera on Vulkan writes 66
tokens a second against llama.cpp's 56 and Ollama's 41; a 95,000-word document's first word after 138 s with the
ROCm add-on (Ollama 144 s, Vulkan 296 s); follow-ups in 0.3-0.4 s (Ollama 2.2 s); the first word after a restart in
0.8 s (Ollama 3.2 s).
