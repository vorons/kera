## Kera 0.1.0 preview 3: the first preview measured on the Minisforum

**What this is.** The third preview download, and the first one tested on your Minisforum (reached over Tailscale,
with Nemotron 3 Nano, the model already in your Ollama). Testing there found five problems, all fixed here: saving a
chat held up the next message, the ROCm add-on couldn't load, guessing could stop a reply for good, some command
lines stopped `kera serve` at once, and a new Kera folder started slowly. No gate has passed yet: Gate 0 needs you to
open the app once (below). Everything not labelled lossy gives exactly the model's own answers.

**How to try it on the Minisforum**

1. Download `kera-v0.1.0-preview.3-windows-x64.zip` below and unzip it anywhere (it replaces preview 2).
2. Double-click `kera.exe` (if Windows warns, "More info", then "Run anyway"). The page measures your computer in
   about 30 seconds and explains it in plain words: this is all Gate 0 asks of you.
3. In a terminal in that folder, `kera serve -m <model.gguf>` runs a model for chat apps (OpenAI and Anthropic
   interfaces); it guesses ahead by itself where that pays, and keeps chats on the SSD so a restart doesn't read
   them again.
4. **For long documents, the ROCm add-on:** unzip `kera-v0.1.0-preview.3-windows-x64-hip-addon.zip` into the same
   folder (folders named `hip` and `.kpack` appear next to `kera.exe`), then add `--backend hip`. On your machine it
   reads a 95,000-word document more than twice as fast as Vulkan; Vulkan writes about a third faster, so it stays
   the default.

**What changed since preview 2**

- **Saved chats no longer hold up the next message** (`docs/NEGATIVE_RESULTS.md` N-005). Kera saved each chat
  right after its reply, so the next message waited, up to 2 seconds by the 12th message. Now it saves once the
  server is idle, keeps only what a resumed chat needs, and copies the graphics chip's memory in a few large
  pieces instead of thousands of small ones.
- **The ROCm add-on works** (N-007): it now carries AMD's maths libraries and their kernels for your chip, and
  Kera says plainly if a file is missing instead of stopping.
- **Guessing can't stop a reply any more** (N-009): on a mixture-of-experts model on a graphics chip, llama.cpp's
  server could check the same few guessed words forever. Found on ROCm; it could happen on Vulkan too.
- **Windows command lines** (N-008): some combinations of options stopped `kera serve` at once, and a model in a
  folder with an accented or non-Latin name couldn't be opened.
- **A new Kera folder or an update starts warm** (N-011): Vulkan's built shaders are now kept in Kera's folder. On
  your machine a fresh copy's first answer started after 3.2 s; with the kept shaders, after 0.18 s.

**Numbers on your Minisforum** (Nemotron 3 Nano 30B-A3B, your Ollama's 22.8 GB file, on the graphics chip; every
engine greedy (temperature 0, top_k 1), with thinking off and answers of up to 256 tokens; the model's own default,
thinking on, wasn't measured)

*Added 9 Nov 2026:* Kera's writing speeds below (1.71 and 1.16 times as fast, 1.30x on a chat, 1.40x rewriting code)
are too high and will be measured again: each prompt was asked three times in a row on one server, and from the
second time Kera's guesser could copy its own earlier answer. The waits for the first word aren't affected.

- Against Ollama 0.30.9 (measured with preview 2): Kera writes 1.71 times as fast (1.45-2.05x by prompt) and
  answered follow-ups in 0.63 s against 1.29 s, before the saved-chat fix brought that to 0.30 s.
- Against stock llama.cpp (the same engine without Kera): 1.16 times as fast on average (1.30x on a chat, 1.40x
  rewriting code, where copying from the chat pays); the same wait before follow-ups (0.30 s); after a restart the
  first word comes 3.7 times sooner (0.65 s), because the chat comes back from the SSD. With guessing turned off,
  Kera's answers are word for word the same as stock llama.cpp's.
- A 95,000-word document: the first word after 136 s with the ROCm add-on, against 150 s for Ollama and 303 s on
  Vulkan; follow-up questions in that chat answered in 0.3 s (Ollama 2.3 s).
- Your machine, as `kera setup` measured it and checked by hand: the SSD reads 2.2 GB/s, the CPU reads memory at
  111 GB/s, the graphics chip at 214 GB/s.

**What's known and not yet done**

- Vulkan rounds more coarsely than ROCm on this chip: on the tiny test models its answers drift from the reference
  more, and on the GLM-5-style one that flipped a near-tie (N-010). ROCm matches the reference.
- Choosing ROCm or Vulkan by itself, per model and document length, comes next (M8).
- The other gates need the bigger models, the Mac and an NVIDIA machine (`docs/STATUS.md`).
