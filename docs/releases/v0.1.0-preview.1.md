## Kera 0.1.0 preview 1: the first Windows download

**What this is.** The first build of Kera you can download and run on the Minisforum. It doesn't run
models faster than llama.cpp yet: it is the base the speed work builds on. When you open it, it
measures your computer, explains in plain words what it found, and lists the models already on your
disk with how fast each should run.

**How to try it on the Minisforum**

1. Download `kera-v0.1.0-preview.1-windows-x64.zip` below and unzip it anywhere.
2. Double-click `kera.exe`. If Windows says "Windows protected your PC", click "More info", then
   "Run anyway" (Kera isn't signed yet).
3. A page opens in your browser. Within about a minute it shows your SSD, memory and graphics chip
   speeds, then "Your models": every `.gguf` file it finds in Kera's folder, LM Studio's, llama.cpp's
   and Hugging Face's (or a folder you add), each with its predicted speed. Nothing is sent anywhere.

In a terminal in the unzipped folder you can also try:

- `kera bench --model <file.gguf>`: the speed test (wait for the first word, prompt speed and writing
  speed on four test prompts). Results go to `%LOCALAPPDATA%\Kera\bench`.
- `kera serve -m <file.gguf>`: llama.cpp's server, which talks to chat apps through the OpenAI and
  Anthropic interfaces, plus Kera's saved chats: each chat's state is kept on the SSD, so going back to an
  old chat, or restarting the server, doesn't mean reading the whole chat again.
- `kera wait --url http://127.0.0.1:8080`: sends one message to a running server (Kera's or your own
  app's) and explains where the wait before the reply went: loading, reading your message, thinking,
  writing.
- `kera plan --model <file.gguf>`: the speed prediction, explained.

In the app, each model has a **Run** button: Kera keeps that model loaded in the background and shows
the address to give chat apps (for example `http://127.0.0.1:8080/v1`). The next time the app starts,
it loads the same model again by itself.

**Models bigger than memory.** If a mixture-of-experts model doesn't fit in the memory Kera measured,
`kera serve` (and the Run button) streams it from the SSD by itself: only the experts each word needs
are read, just before they're used, and the answers stay exactly the same as running from memory.
`--stream kera` forces it on, `--stream off` turns it off, and `--stream-budget-gb N` sets how much
memory the experts may use. This is the first version of M5 and hasn't been measured on the
Minisforum yet.

**What was built**

- **M0, Foundations:** the app (one program, a local web page, the Kera logo), auto-setup (SSD speed
  with reads that skip Windows' file cache, memory speed, the graphics chip), the speed test, a check
  that llama.cpp runs each of your target model designs exactly like the official reference code (all
  four match on tiny copies; on the way it found the reference code for Nemotron disagreeing with
  itself, logged as N-001), and the automatic builds and tests on GitHub.
- **Parts of later milestones that don't need your hardware:** saved chats on the SSD (M2), `kera
  wait` (M2), each model card's recommended sampling for thinking on, thinking off and tool calls,
  used when a chat app doesn't set its own (M2), the Run button (M2), the speed planner in the app
  (M3), a controller that picks how many words to guess ahead at each step from measured speed (M4),
  and streaming models bigger than memory from the SSD (M5).
- llama.cpp release b11619 inside, with Vulkan for the Radeon 8060S, and four small hooks: saved
  chats, the guess controller, streaming and the model card's sampling (listed in
  `docs/UPSTREAM_PATCHES.md`).

**Did the gate pass?** Not yet. Gate 0 needs you: open this download on the Minisforum and see your
speeds explained. The agent then checks those numbers by hand (within 10%) and measures stock
llama.cpp on the bench models there (the "F0 baselines"). Both need the agent to reach the Minisforum,
which waits on the Tailscale and SSH steps in `docs/STATUS.md`. The streaming gates (2 to 5) need the
Minisforum too.

**Numbers so far** (none from your hardware yet; these are from the cloud test machine):

- Reference check: llama.cpp matches the reference code to within 0.0008 in log-probability on all
  four designs (the limit is 0.02).
- Saved chats: after a restart, 909 of a 913-token chat came back from the SSD instead of being read
  again (Mamba-hybrid design), with the same answer as without the restart.
- Guess controller: on a tiny test model, writing with the controller ran at 194 words a second
  against 52 without guessing (one word a second is about 45 words of text a minute). Tiny models
  exaggerate this; real numbers come from the Minisforum.
- Streaming: Nemotron 3 Nano (an 18 GB file) on a cloud machine with 15 GB of memory, on new text:
  stock llama.cpp wrote 3.1 to 4.6 words a second, Kera's streaming 4.8 to 5.6 (22% to 54% faster),
  with exactly the same answers. The cloud machine's disk is slow and shared; the Minisforum's SSD is
  much faster, so its numbers will differ.

**What comes next.** The rest of M1's risk tests, guessing ahead for streamed models (M6), and
measuring all of this on the Minisforum once the agent can reach it.

  and the baselines there.
